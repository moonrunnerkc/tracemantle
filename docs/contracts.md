# Input, dependency and report contracts

Sources are regular UTF-8 files, with an optional leading BOM. CRLF and CR are normalized for analysis; bundle hashing uses original bytes. The YAML opener and closer must be standalone `---` lines at column zero, optionally followed by horizontal whitespace. An opener without a closer is an error. Empty frontmatter parses as an empty mapping; required-field checks still apply. Multiline values are valid. Manifest description identity supports strings and null (for history of missing/empty descriptions); other description types are rejected before canonical JSON hashing. Quote a date-like description to keep it a string. Invalid YAML date/time and numeric scalar conversions become bounded `parse.error` diagnostics at the scalar’s full-file line; unrelated batch files continue. Ordinary validation still rejects null descriptions. Duplicate keys and non-string mapping keys, including YAML merge keys, are rejected. Bounded nonrecursive aliases are accepted and reported as portability advice. Recursive aliases are rejected. Source locations count from line one of the complete file.

Each read is limited to the selected cap plus one byte, including a file that grows during the read. SKILL.md is capped at 4 MiB, config at 1 MiB, legacy history at 8 MiB and imports at 5 MiB. An external adapter file and a verified-profile registry are each capped at 1 MiB, and an evidence signature sidecar at 64 KiB. YAML limits are depth 40, 20,000 nodes and 100 aliases; expanded alias structure has the same depth/node budget. JSON limits are depth 40 and 100,000 nodes, with duplicate keys and nonfinite numbers rejected. The shared decoder validates every numeric value at the root or inside objects/arrays before adapters select rows or compute digests. Exponent overflow such as `1e999` and `-1e999` is rejected alongside `NaN`, `Infinity` and `-Infinity`. Finite floats, including subnormal and underflow-to-zero values, retain Python JSON conversion and canonical serialization; rejected values are never coerced. A skill batch is limited to 10,000 files and 128 MiB of source bytes. Resource closure is bounded to 32 levels, 10,000 resource paths/expanded Markdown files and 128 MiB. Immutable history reads are bounded to 10,000 records and 128 MiB total. Heuristic graphs are limited to 100,000 body lines and 10,000 nodes/headings. Expected encoding, resolution and filesystem errors become diagnostics; unrelated programming errors are not swallowed.

Directory symlinks are not traversed during discovery. Resolved duplicate source paths are validated once. Explicit source-file symlinks may resolve to regular files; dangling links, cycles and nonregular sources fail cleanly. A bundle manifest refuses symlinks and nonregular resources as incomplete identity rather than following them. Manifest names must be NFC-normalized, case-unambiguous relative paths with no controls, backslashes, drive prefixes or traversal segments. Files are sorted by normalized path; identity includes original bytes, full SHA-256, size and whether any executable bit is set. Only `.git`, `__pycache__`, `.DS_Store` and the legacy ledger are excluded. Exclusion applies to the hash only: a `__pycache__` entry anywhere, or a `.git` entry below the bundle root, can change what runs, so its presence is reported as `Unhashed runtime content` and the manifest is incomplete. Evidence destinations must be outside evaluated bundles.

Markdown supports inline/image links (including angle-bracket destinations and titles), reference links/definitions, HTML href/src links, source/file/include directives and standalone path-like inline code. Inline code containing a path separator is an ambiguous mention, not an assertion that a packaged file exists. It produces `references.uncertain` and incomplete dependency coverage, whether or not the file exists. Contained candidate edges are retained, but ambiguous mentions are not recursively interpreted as required documents. Explicit links and source/file/include directives remain assertions: missing resources and escapes are errors. A link to a directory or other nonregular path names no file a change could match, so it produces `references.uncertain` and incomplete coverage. Fences use backticks or tildes, closed by a matching character and at least the opening delimiter length. Indented code requires four columns beyond the current container and cannot interrupt a paragraph. Ordinary bullet and numbered lists, nested items, blank-separated list continuations and four-column tab stops are recognized. List markers with one through four columns of padding establish continuation indentation; wider padding starts indented code. List-container depth is capped at 32; deeper nesting marks coverage incomplete. Links, images, definitions, HTML links and directives inside code blocks or matched inline code spans are not dependencies. Inline spans use equal-length backtick runs and may span lines within a block; adjacent list items and headings cannot close each other's spans. Code spans and links are read in one left-to-right pass, as CommonMark binds them (since the release after 1.9.0): whichever opens first wins, link syntax inside a span is not a link, and a link's destination and title are raw text in which a backtick opens no span. Before that, spans were blanked first, so a title or definition could run across a blanked span and absorb a later link. Outside spans, an odd run of preceding backslashes escapes the first backtick, while an even run leaves it available as a delimiter. Inside spans, backslashes are literal and do not escape closing backticks. Unmatched delimiters remain visible.

Links are read per paragraph-level block, following [CommonMark 0.31.2 links](https://spec.commonmark.org/0.31.2/#links) and [link reference definitions](https://spec.commonmark.org/0.31.2/#link-reference-definitions). An inline link or image may have text with balanced or backslash-escaped brackets, text that spans lines, and a destination and title that start on the following line. Destinations decode backslash escapes and entity references before the existing percent-decoding; parentheses must balance, to at most 32 levels. A backslash before a space ends a CommonMark destination. Renderers that predate CommonMark keep the space, so when the CommonMark reading of such a link or definition does not parse, the destination with the space is governed as well, and the text is still read as CommonMark inline content. Reference labels are compared after case folding, trimming and collapsing internal whitespace. A definition's label, destination and title may each continue on the next line. CommonMark gives effect to the first definition of a label. The tokenizer cannot always identify that line, because it reads definitions inside HTML blocks too and compares labels slightly more loosely, so every distinct destination defined for a label is a dependency, up to eight; beyond eight, coverage is incomplete. The first definition is therefore always governed and no earlier look-alike can hide it. Every bracket pair that matches a defined label counts as a use, a definition counts as a use of its own label, and a definition-shaped line inside a paragraph is recorded like a definition although CommonMark reads it as text. This deliberately includes more than CommonMark renders as a link, because an extra governed helper is safe and a missed one permits stale evidence reuse. For the same reason link syntax inside a definition's own destination or title is governed: some renderers reject a definition that CommonMark accepts, for example one with an empty title, and read its line as text. One consequence is that a duplicate definition naming a missing file is reported as a broken link. Coverage is marked incomplete for: bracketed text immediately followed by a parenthesized destination that does not parse; a definition-shaped line whose destination does not parse; a backtick inside an inline HTML tag, comment or autolink, which are not parsed and where code-span matching can hide later links; and a body containing a vertical tab, form feed, U+001C to U+001E, U+0085, U+2028 or U+2029, which some tools treat as line breaks and CommonMark does not. A list item that is empty, or ordered with a number other than 1, does not interrupt a paragraph and is read as paragraph text. Failed destination scans within one block are limited to twice the block's length plus 1,024 characters; ordinary prose never reaches that, and a crafted block that does is already incomplete and has no further inline destinations parsed. A resource is reported at the line where its destination or label use begins.

HTML blocks follow [CommonMark 0.31.2 section 4.6](https://spec.commonmark.org/0.31.2/#html-blocks) (since 1.9.0). All seven start conditions and their end conditions are recognized, including that only a lone open or closing tag cannot interrupt a paragraph and that a block ends with its list item. The lines of an HTML block are raw HTML: a fence marker there opens no code block and a backtick pairs no code span, so neither can hide a later link. Nothing in the block is rendered or executed. `href` and `src` attributes, link syntax and directives inside it are still read as dependencies, which again includes more than CommonMark renders as a link. Before 1.9.0 a fence marker inside an HTML block was read as a fence and could hide a later link while coverage stayed complete.

Renderers do not agree on every block boundary. Where a recognized disagreement applies, the document is tokenized once per reading and every resource named under any reading is a dependency, so coverage stays complete without choosing a renderer (since the release after 1.9.0; in 1.9.0 these forms marked coverage incomplete). Lines, headings and source locations always follow the CommonMark 0.31.2 reading. The readings are: `<textarea>` as a raw text block or not, and whether `</textarea>` ends one (0.31.2 against 0.29, which GitHub Flavored Markdown follows); `<search>` as a block tag (added in 0.31); `<source>` as a block tag (0.29 only); a declaration that starts with a lowercase letter (0.31.2, but not 0.29 or markdown-it); a blank line inside a comment or `<pre>`-style block within a list item, which markdown-it ends and CommonMark continues; whether a complete link reference definition closes its paragraph, so that the next line starts a block (markdown-it) or continues the paragraph (cmark); a line of hyphens after definitions that consume their paragraph, which cmark reads as text and commonmark.js as a thematic break or list item; and code span delimiters in a block that also holds an unclosed backtick run, which markdown-it and cmark can read as literal text because of how they remember failed searches for a closing run. That last reading takes every backtick in such a block as literal, which covers the forms found by differential testing but is an approximation of those renderers, not an emulation. A Setext underline of `=` after such definitions is paragraph text under every reading and is resolved exactly. At most eight readings are tokenized for one document; a document that combines more of these forms is marked incomplete. One definition is tracked across at most 16 lines while its paragraph holds only definitions; a longer one marks coverage incomplete.

Only standalone path-like span contents are resource candidates. Anchors and external schemes are not local files. A bare `report.json` inline-code mention is classified as a potential generated output; a path such as `scripts/helper.py` is an ambiguous resource candidate. Unsupported template/dynamic paths, blockquote containers, same-line nested list markers and lazy outdented list continuations mark dependency coverage incomplete. These container cases require a full Markdown block parser to establish exact dependencies; the limited tokenizer retains discoverable resources but does not claim complete coverage. Arbitrary programming-language imports, shell expansion and runtime-created dependencies are not inferred. A trusted check must explicitly declare its inputs and whether dependency coverage is complete; incomplete coverage requires full relevant-suite reruns on changes.

Standard API validation returns `ValidationResult`; its `valid` describes that file's errors, independent of strict policy. CLI validation JSON envelope schema 2 adds `tool`, `version`, `schema_version`, `gate` and `tokenizer` to the file summaries/results. Graph and prompt emit modes also emit one JSON object for single or multiple inputs. Single-graph fields and prompt fields are retained; multiple inputs appear under `results`. Historical ledger JSON keeps its v1 content fields. Product commands use envelope schema 1, with `command`, `exit_code` and `result`; manifest, check-evidence and imported history each have explicit content-schema versions.

Ignore prefixes are applied after merging symbolic, graph, model-judgment and history diagnostics. A skill may also declare file-scoped prefixes in a frontmatter comment, `# tracemantle: ignore=sizing, compat.unverified` (since 1.8.0). They apply at the same point, to that file only, and never to `ignore.` diagnostics: each directive is reported as an `ignore.inline` note, and unusable tokens as `ignore.inline-invalid` warnings. Only a comment-only line is a directive. The same text inside a literal or folded block scalar, with any chomping or indentation indicator, or inside a multiline quoted string, is string content and suppresses nothing; a comment after such a scalar still works. `--no-inline-ignores` (config key `no-inline-ignores`, Action input `no-inline-ignores`) applies no directive and reports each as `ignore.inline-refused` instead of `ignore.inline`. An explicit flag overrides project configuration, so candidate content cannot turn the refusal off. Discovered project configuration is itself candidate-controlled: pass an explicit `--config` from trusted tooling when validating contributions you have not reviewed. Ignore settings affect file validation only and never the trusted release comparison. The library `validate()` reports the directive; suppression, like `--ignore`, is applied by the CLI. Final exit calculation runs after history diagnostics. Human output escapes untrusted C0/C1 controls, lone surrogates, bidirectional formatting controls and Unicode line/paragraph separators; Markdown also escapes syntax delimiters. JSON preserves source values reversibly and uses JSON escaping. Quiet validation skips score explanations and report rendering. Prompt variants contain untrusted skill instructions as quoted task material, not instructions executed by TraceMantle.

The 1.6.1 fixes enforce these code-context and description-type boundaries. They also return a schema-2 validation error envelope for configuration load/discovery failures requested with `--format json`: `gate` contains `passed: false` and `exit_code: 2`, `results` is empty, and `errors` contains objects with an `error` message. Product input errors retain schema 1 with `exit_code: 2` and `result.state: infrastructure-error`. A malformed project configuration prevents selecting settings for the invocation; malformed source files still continue as independent batch results where documented. Human history warnings and missing-ledger paths use the same control escaping as successful reports, independent of color settings.

Since 1.9.0, every expected validation input failure uses that schema-2 error envelope when `--format json` is selected and `--quiet` is not: a missing path, a directory with no `SKILL.md`, mixed project roots, a missing, malformed or invalid configuration, a missing, oversized, non-UTF-8 or binary ingest response, an unusable `--changed-since` revision or repository, incompatible modes and option combinations rejected after parsing. Stdout carries exactly one JSON object and the exit status is 2. Text formats and `--quiet` keep their stderr message and print nothing on stdout. `--help` and `--version` are unchanged. Arguments that argparse itself rejects (an unknown option, an invalid choice, a missing value or no path) remain usage errors on stderr with exit 2 in every format, because no output format has been established. A format selected only by project configuration applies once that configuration has loaded. A malformed skill inside a batch is still a `parse.error` result, not an envelope error. Unexpected exceptions are not converted.

The 1.6.1 delimiter and indentation corrections follow [CommonMark 0.31.2 code spans](https://spec.commonmark.org/0.31.2/#code-spans), [backslash escapes](https://spec.commonmark.org/0.31.2/#backslash-escapes) and [list items](https://spec.commonmark.org/0.31.2/#list-items) for the supported subset. This is dependency analysis, not a general Markdown renderer. [Regression verification](verification/audit-1.6.1/acceptance.md#dependency-and-numeric-boundary-corrections) records the trusted-Git and authentic-export controls.

Setext underlines of one or more identical `=` or `-` characters, with up to three spaces relative to the supported list container and trailing spaces/tabs, terminate the preceding paragraph before inline span matching. All lines of multiline heading content share one inline block. Four-column indentation within an existing paragraph, escaped underlines, mixed characters and embedded spaces do not become Setext boundaries. ATX headings with up to three spaces and homogeneous thematic breaks (including spaced markers) also delimit inline spans. Fenced and indented code are resolved first. Unsupported container contexts retain incomplete coverage. Setext support here establishes dependency boundaries; the heuristic capability-heading index continues to use ATX headings. See [CommonMark Setext headings](https://spec.commonmark.org/0.31.2/#setext-headings) and [1.6.1 verification](verification/release-1.6.1/acceptance.md).


Since 1.7.0, neutral JSON uses the same 5 MiB source limit and bounded full-document
decoder. Approval envelopes are limited to 64 KiB and bind complete evidence
digests. Policy schema 2 explicitly authorizes scoped automation; schema 1 remains
digest-only. See [automation approval](evidence-workflow.md#protected-automation)
for the run context, expiration, replay and revocation contract. No evaluator
execution or network dependency is added to ordinary validation or data import.

## Skill-root reference dialect

The Python API supports an explicit `DocumentSettings(reference_format="skill-base-dir")` interpretation. Pass that document to `create_manifest(..., document=parse(..., settings=settings))` and use the same settings for validation. The default `relative` interpretation leaves `{baseDir}` unresolved and coverage incomplete. No candidate frontmatter selects a dialect. A deployment must bind this setting to its trusted checker/configuration identity; changing it invalidates prior evidence.

In this dialect, exactly the leading `{baseDir}/` in a reference denotes the selected skill root, including in transitive Markdown documents. This matches the SARIF skill's packaged `resources/` layout and Trail of Bits' [path convention](https://github.com/trailofbits/skills/blob/1f68e03536f7980d4c0e6869596f708043a19443/AGENTS.md#path-handling). It is a static interpretation, not a claim that every host substitutes the variable; upstream [tracks that portability limitation](https://github.com/trailofbits/skills/issues/8). Other variables remain unresolved. URL decoding occurs once before interpretation; rooted suffixes, backslashes and drive prefixes fail. Resolution and symlink containment use the ordinary skill boundary. Decoded control characters are rejected before URL parsing can strip them. Template suffixes are literal, including `~`; legacy home expansion applies only to ordinary references. No shell, environment expansion or arbitrary template evaluation is introduced.

This dialect does not disambiguate inline prose. No ignore declarations or natural-language intent heuristics are supplied. If actual coverage remains incomplete, the release comparison remains unknown even for an unchanged candidate. Use the full relevant suite, and do not treat a per-check historical pass as permission to bypass an unknown overall gate.

## Experimental per-check scope interpretation

The preceding unchanged-candidate restriction remains the default for legacy
policies. Policy schema 3 can explicitly select a reviewed closed input scope for
a static or deterministic maintenance check. It does not change Markdown parsing,
classify author intent, clear warnings or set the bundle complete flag. See the
[evidence contract](evidence-workflow.md#experimental-closed-check-scopes).

New manifests emit content schema 2 with `resource_errors`: the subset of issues
that are explicit resource failures rather than inferred-coverage uncertainty.
The file-based bundle SHA-256 still uses the original schema-1 identity algorithm.
Schema-1 manifests round-trip unchanged; their error distinction is unknown and
they cannot authorize closed-scope reuse. Schema-2 errors must also appear in
issues and cannot coexist with complete=true. Regenerate manifests through trusted
tooling; imported metadata is not a proof of the filesystem's state.
