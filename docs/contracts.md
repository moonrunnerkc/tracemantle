# Input, dependency and report contracts

Sources are regular UTF-8 files, with an optional leading BOM. CRLF and CR are normalized for analysis; bundle hashing uses original bytes. The YAML opener and closer must be standalone `---` lines at column zero, optionally followed by horizontal whitespace. An opener without a closer is an error. Empty frontmatter parses as an empty mapping; required-field checks still apply. Multiline values are valid. Manifest description identity supports strings and null (for history of missing/empty descriptions); other description types are rejected before canonical JSON hashing. Quote a date-like description to keep it a string. Invalid YAML date/time and numeric scalar conversions become bounded `parse.error` diagnostics at the scalar’s full-file line; unrelated batch files continue. Ordinary validation still rejects null descriptions. Duplicate keys and non-string mapping keys, including YAML merge keys, are rejected. Bounded nonrecursive aliases are accepted and reported as portability advice. Recursive aliases are rejected. Source locations count from line one of the complete file.

Each read is limited to the selected cap plus one byte, including a file that grows during the read. SKILL.md is capped at 4 MiB, config at 1 MiB, legacy history at 8 MiB and imports at 5 MiB. YAML limits are depth 40, 20,000 nodes and 100 aliases; expanded alias structure has the same depth/node budget. JSON limits are depth 40 and 100,000 nodes, with duplicate keys and nonfinite numbers rejected. The shared decoder validates every numeric value at the root or inside objects/arrays before adapters select rows or compute digests. Exponent overflow such as `1e999` and `-1e999` is rejected alongside `NaN`, `Infinity` and `-Infinity`. Finite floats, including subnormal and underflow-to-zero values, retain Python JSON conversion and canonical serialization; rejected values are never coerced. A skill batch is limited to 10,000 files and 128 MiB of source bytes. Resource closure is bounded to 32 levels, 10,000 resource paths/expanded Markdown files and 128 MiB. Immutable history reads are bounded to 10,000 records and 128 MiB total. Heuristic graphs are limited to 100,000 body lines and 10,000 nodes/headings. Expected encoding, resolution and filesystem errors become diagnostics; unrelated programming errors are not swallowed.

Directory symlinks are not traversed during discovery. Resolved duplicate source paths are validated once. Explicit source-file symlinks may resolve to regular files; dangling links, cycles and nonregular sources fail cleanly. A bundle manifest refuses symlinks and nonregular resources as incomplete identity rather than following them. Manifest names must be NFC-normalized, case-unambiguous relative paths with no controls, backslashes, drive prefixes or traversal segments. Files are sorted by normalized path; identity includes original bytes, full SHA-256, size and whether any executable bit is set. Only `.git`, `__pycache__`, `.DS_Store` and the legacy ledger are excluded. Evidence destinations must be outside evaluated bundles.

Markdown supports inline/image links (including angle-bracket destinations and titles), reference links/definitions, HTML href/src links, source/file/include directives and standalone path-like inline code. Fences use backticks or tildes, closed by a matching character and at least the opening delimiter length. Indented code requires four columns beyond the current container and cannot interrupt a paragraph. Ordinary bullet and numbered lists, nested items, blank-separated list continuations and four-column tab stops are recognized. List markers with one through four columns of padding establish continuation indentation; wider padding starts indented code. List-container depth is capped at 32; deeper nesting marks coverage incomplete. Links, images, definitions, HTML links and directives inside code blocks or matched inline code spans are not dependencies. Inline spans use equal-length backtick runs and may span lines within a block; adjacent list items and headings cannot close each other's spans. Outside spans, an odd run of preceding backslashes escapes the first backtick, while an even run leaves it available as a delimiter. Inside spans, backslashes are literal and do not escape closing backticks. Unmatched delimiters remain visible.

Only standalone path-like span contents are resource candidates. Anchors and external schemes are not local files. A bare `report.json` inline-code mention is classified as a potential generated output; a path such as `scripts/helper.py` is a resource. Unsupported template/dynamic paths, blockquote containers, same-line nested list markers and lazy outdented list continuations mark dependency coverage incomplete. These container cases require a full Markdown block parser to establish exact dependencies; the limited tokenizer retains discoverable resources but does not claim complete coverage. Arbitrary programming-language imports, shell expansion and runtime-created dependencies are not inferred. A trusted check must explicitly declare its inputs and whether dependency coverage is complete; incomplete coverage requires full relevant-suite reruns on changes.

Standard API validation returns `ValidationResult`; its `valid` describes that file's errors, independent of strict policy. CLI validation JSON envelope schema 2 adds `tool`, `version`, `schema_version`, `gate` and `tokenizer` to the file summaries/results. Graph and prompt emit modes also emit one JSON object for single or multiple inputs. Single-graph fields and prompt fields are retained; multiple inputs appear under `results`. Historical ledger JSON keeps its v1 content fields. Product commands use envelope schema 1, with `command`, `exit_code` and `result`; manifest, check-evidence and imported history each have explicit content-schema versions.

Ignore prefixes are applied after merging symbolic, graph, model-judgment and history diagnostics. Final exit calculation runs after history diagnostics. Human output escapes untrusted C0/C1 controls; Markdown also escapes syntax delimiters. JSON preserves source values reversibly and uses JSON escaping. Quiet validation skips score explanations and report rendering. Prompt variants contain untrusted skill instructions as quoted task material, not instructions executed by TraceMantle.

The 1.6.1 fixes enforce these code-context and description-type boundaries. They also return a schema-2 validation error envelope for configuration load/discovery failures requested with `--format json`: `gate` contains `passed: false` and `exit_code: 2`, `results` is empty, and `errors` contains objects with an `error` message. Product input errors retain schema 1 with `exit_code: 2` and `result.state: infrastructure-error`. A malformed project configuration prevents selecting settings for the invocation; malformed source files still continue as independent batch results where documented. Human history warnings and missing-ledger paths use the same control escaping as successful reports, independent of color settings.

The 1.6.1 delimiter and indentation corrections follow [CommonMark 0.31.2 code spans](https://spec.commonmark.org/0.31.2/#code-spans), [backslash escapes](https://spec.commonmark.org/0.31.2/#backslash-escapes) and [list items](https://spec.commonmark.org/0.31.2/#list-items) for the supported subset. This is dependency analysis, not a general Markdown renderer. [Regression verification](verification/audit-1.6.1/acceptance.md#dependency-and-numeric-boundary-corrections) records the trusted-Git and authentic-export controls.

Setext underlines of one or more identical `=` or `-` characters, with up to three spaces relative to the supported list container and trailing spaces/tabs, terminate the preceding paragraph before inline span matching. All lines of multiline heading content share one inline block. Four-column indentation within an existing paragraph, escaped underlines, mixed characters and embedded spaces do not become Setext boundaries. ATX headings with up to three spaces and homogeneous thematic breaks (including spaced markers) also delimit inline spans. Fenced and indented code are resolved first. Unsupported container contexts retain incomplete coverage. Setext support here establishes dependency boundaries; the heuristic capability-heading index continues to use ATX headings. See [CommonMark Setext headings](https://spec.commonmark.org/0.31.2/#setext-headings) and [1.6.1 verification](verification/release-1.6.1/acceptance.md).
